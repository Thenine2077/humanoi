ซิม กับ ของจริง

ฝั่งซิมสมบูรณ์แล้ว ฝั่งของจริงยังมีช่องว่างที่ roadmap วางไว้เติมภายหลัง

ในซิม (Gazebo) — มีครบ

  • ตัวหุ่น + ล้อ + LiDAR จาก URDF
  • Odometry ground-truth จาก OdometryPublisher
  • การเคลื่อนที่ kinematic — holonomic เต็ม สไลด์ข้างได้
  • โลก ห้อง 10×8 m + กล่อง 3 ชิ้น (room.sdf)

ของจริง — ยังขาด

  • Odometry — มอเตอร์ไม่มี encoder ยังไม่มีแหล่ง /odom
  • คุมความเร็ว — relay คุมแค่ทิศ ความเร็วหมุนลูกบิด (รอ Cytron MDDS10)
  • LiDAR จริง · Raspberry Pi 5 · IMU (roadmap Stage 3)
  • รีโมท RC FlySky — ตอนนี้แทนด้วยคีย์บอร์ด
  • แขน AR4 ×2 (Teensy 4.1 + MoveIt) + safety interlock แขนพับก่อนฐานวิ่ง — M15–M18

เขียนพฤติกรรมการตัดสินใจได้ที่ไหน

Nav2 เปิดให้แทรกตรรกะได้หลายชั้น — ตรรกะระดับงานควรอยู่ชั้นบนสุด ไม่ยัดใน BT ของ Nav2

Behavior Tree แก้ไฟล์ XML ที่ bt_navigator รัน — จัดเรียง node ใหม่ (เช่น "แบตต่ำ → กลับ dock"), เพิ่ม timeout/retry, หรือเขียน BT node เอง (C++) เครื่องมือ: Groot2
Plugin เขียนแทนได้ทุกจุด: planner · controller · behavior (ท่ากู้) · costmap layer (โซนห้ามเข้า / โซนช้า) · progress & goal checker · waypoint task executor ทำงานตอนถึงแต่ละ waypoint
Orchestrator โหนดแยกที่เรียก action ของ Nav2 (NavigateToPose · FollowWaypoints) — เป็น state machine หรือ BT ของตัวเอง จัดการ "จะไปไหน ทำอะไร เมื่อไหร่" + สั่งแขน AR4 แพ็กเกจ humanoi_mission (ยังไม่สร้าง)
ก้าวถัดไปฝั่งของจริง — odometry. อินเทอร์เฟซคือ /odom + TF odom→base_footprint — ท้ายน้ำไม่ต้องแก้ ทางเลือก: (1) laser odometry จาก LiDAR อย่างเดียว ไม่แตะฮาร์ดแวร์ ทดสอบ Nav2 บนหุ่นจริงได้ทันที · (2) dead-wheel pod — ล้อ omni อิสระ + encoder ไม่ไถลเหมือนล้อ mecanum (roadmap Stage 2) · (3) fuse ทั้งคู่ + IMU ด้วย robot_localization EKF
