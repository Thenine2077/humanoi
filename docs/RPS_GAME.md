# เกมเป่ายิ้งฉุบ (humanoi_games)

หุ่นเล่นเป่ายิ้งฉุบกับคน: แขนซ้าย (ติดมือ AmazingHand) + กล้อง Astra บนเสา

1. แขนไปท่าตั้ง `rps_ready` (ท่าที่สอนเอง) มือกำหลวมๆ นิ้วกาง (ท่า `windup`)
2. ข้อ 1 ยกขึ้น-ลง 3 ครั้ง = เป่า - ยิ้ง - ฉุบ (ราว 8.6 วินาที ที่ 5°)
3. จังหวะ "ฉุบ" มือออกท่าที่สุ่มไว้: ค้อน (กำสุด) / กระดาษ / กรรไกร
4. กล้องดูมือผู้เล่น 1.2 วินาทีหลัง "ฉุบ" แล้วตัดสิน — แขนไปท่าโชว์ให้ถึงก่อน แล้วมือค่อยทำท่า
   - หุ่นแพ้ (ผู้เล่นชนะ) → แขนสลับ `victory_pose` → `lose_pose` 3 รอบ → มือชูนิ้วโป้ง (ไลค์)
   - หุ่นชนะ (ผู้เล่นแพ้) → แขนไป `victory_pose` → มือชู 2 นิ้ว ขยับแบบกรรไกร
   - เสมอ → เป่าใหม่ (ไม่เกิน 2 ครั้ง)
   - ไม่เห็นมือ → ส่ายนิ้ว
   - ท่าโชว์ที่ยังไม่ได้สอน = แขนค้างที่ท่าตั้ง มือทำท่าเหมือนเดิม
5. ค้างท่า 3 วินาที แล้วแบมือ แล้ว**แขนกลับท่าตั้งผ่าน move_readyP1 → move_readyP2 → rps_ready**
   (`return_moves`) — ไม่เหวี่ยงตรงๆ เพราะข้อ 1 รับน้ำหนักทั้งแขนแบบนั้นไม่ไหว
   (ตอนเริ่มเกม ถ้าแขนอยู่ห่างท่าตั้งเกิน 5° ก็เดินทางนี้ก่อนเหมือนกัน)
6. **ผู้เล่นชูนิ้วชี้ 1 นิ้วค้างไว้ราว 1 วินาที = เล่นตาใหม่** — รอ 1 วินาที แล้วเป่า วนไปเรื่อยๆ
   (รอนิ้วชี้ได้ 60 วินาทีหลังจบเกม เกินนั้นต้องสั่ง `arm rps play` ใหม่ · ชูแวบเดียวไม่นับ)

## ตั้งค่าครั้งแรก

**สอนท่า** (เปิด `arm start` + `arm moveit` จัดท่าแล้วสอน):

```bash
arm teach left rps_ready    # จำเป็น — ท่าตั้งก่อนเป่า ให้มืออยู่หน้ากล้อง ยื่นไปข้างหน้า
arm teach left victory_pose # ไม่บังคับ — ท่าแขนตอนหุ่นชนะ (ชู 2 นิ้ว) ไม่มี = แขนค้างที่ท่าตั้ง
arm teach left lose_pose    # ไม่บังคับ — ท่าแขนตอนหุ่นแพ้ (ชูนิ้วโป้ง)
```

ทิศ "ขึ้น" ของข้อ 1 เกมคำนวณเองจากท่าตั้ง (แขนติดข้างเสา แกนข้อ 1 นอนขวาง ทิศขึ้นจึงขึ้นกับท่า)
— log บอก เช่น `ยกขึ้น = ข้อ 1 +8° (มือขึ้นราว 4.6 ซม.)` ถ้าขึ้นไม่ถึง 2 ซม. แปลว่ามือเกือบอยู่บนแนวแกนข้อ 1
ให้สอนท่าตั้งใหม่ให้มือยื่นไปข้างหน้ามากขึ้น

**มือ AmazingHand → Pi:** Waveshare Bus Servo Adapter (A) เสียบ USB เข้า Pi (เกมหาเอง: CH343 `1a86:55d3`)
- ไฟเซอร์โว **ห้ามเกิน 7.4 V** — โหนดมือเช็กเองก่อนเปิดแรงบิดทุกครั้ง: ต้องครบ ID 1-8 และไฟ 4.8-7.4 V
  ไม่ผ่าน = ไม่ขยับ บอกเหตุผลใน log
- ปิดโปรแกรมอื่นที่ใช้พอร์ตมือก่อน (tools\\*.py, robot_hand.py) — เปิดพอร์ตได้ทีละโปรแกรม

**คาลิเบรตนิ้ว (ครั้งแรก / ท่ามือดูแปลก):** ค่ากลางของแต่ละ servo (MiddlePos) ยังเป็นค่าของมือตัวอย่างจนกว่าจะตั้งเอง

```bash
arm hand-calibrate        # ปิดเกมก่อน (Ctrl+C ที่หน้าต่าง arm rps) — ใช้พอร์ตมือเดียวกัน
```

ทีละนิ้ว: นิ้วที่ตั้งยืดตรง นิ้วอื่นกำ — กด `l`/`r` (เอียง) `f`/`b` (งอหน้า/หลัง) จนนิ้วตั้งตรงแนวฝ่ามือ
(ใส่ตัวเลขต่อท้ายได้ เช่น `l3`), `o`/`c` ดูท่าแบ/กำ, `n` บันทึกแล้วไปนิ้วถัดไป, `q` บันทึกแล้วออก, `x` ออกไม่บันทึก
เริ่มใหม่ทั้งหมด: `arm hand-calibrate --reset` (ค่าเดิมเปลี่ยนชื่อเป็น `.bak-<เวลา>` ไม่ลบ)
ค่าเก็บที่ `ros2_ws/src/humanoi_games/config/middle_pos.json` บน Pi — เปิดเกมใหม่ถึงจะใช้ค่าใหม่
(ไฟล์นี้อยู่บน Pi เท่านั้น ก่อน commit ให้ดึงกลับมา PC เหมือน programs.yaml)

**ไลบรารีใน container บน Pi** (อยู่ใน `docker/Dockerfile` แล้ว — build image ใหม่ครั้งหน้าจะมีเอง
ถ้ายังไม่ได้ build ใหม่ ลงใน container ที่รันอยู่ได้เลย หายเมื่อสร้าง container ใหม่):

```bash
docker exec humanoi_ros bash -c 'apt-get update && apt-get install -y --no-install-recommends python3-pip python3-matplotlib \
  && pip3 install --break-system-packages rustypot==1.13.1 \
  && pip3 install --break-system-packages --no-deps mediapipe==1.1.1 "absl-py~=2.3" "flatbuffers~=25.9" certifi'
```

`--no-deps` สำคัญ: ถ้าไม่ใส่ mediapipe จะลาก numpy 2 มาทับของ ROS แล้วโหนดอื่นพัง
(container ที่รันอยู่บน Pi ลงครบแล้วเมื่อ 20 ต.ค. — numpy 1.26.4 / cv2 4.6.0 เหมือนเดิม)

## เล่น

```bash
arm start                 # หน้าต่าง 1 — ระบบแขน (ห้ามเปิด arm player พร้อมกัน: สั่งแขนเดียวกัน)
arm rps                   # หน้าต่าง 2 — เปิดเกม (เกม + มือ + ตา + กล้อง ถ้ากล้องยังไม่เปิด)
arm rps play              # หน้าต่าง 3 — เล่นตาแรก รอจนจบแล้วบอกผล (ตาต่อไป: ผู้เล่นชูนิ้วชี้)
arm rps stop              # หยุดกลางคัน · หยุดฉุกเฉิน = ปิดสวิตช์ไฟแขน
```

ผู้เล่นยื่นมือให้กล้องบนเสาเห็น (เหนือโต๊ะหน้าหุ่น) แล้วออกท่าตอน "ฉุบ" ค้างไว้ราว 2 วินาที
- กรรไกร = ชี้ + กลางเหยียด นาง + ก้อยพับ (นิ้วโป้งไม่นับ)
- ชูนิ้วชี้อย่างเดียว = เล่นใหม่ (ภาพใน Foxglove ขึ้น `ONE (play again)`)
- ดูว่ากล้องเห็นอะไร: Foxglove → Image panel → `/rps/vision/image/compressed`

**ทดสอบโดยไม่มีกล้อง/มือ:**

```bash
arm rps random            # สุ่มท่าแทนผู้เล่น
arm rps camera pump_deg:=4   # ปรับค่าได้ตอนเปิดเกม (ชื่อ:=ค่า ของตารางด้านล่าง ที่เป็น launch arg)
arm rps random nohand     # + ไม่ต่อมือ (log ท่าแทน)
arm rps topic             # ส่งท่าผู้เล่นเอง (อีกหน้าต่าง):
ros2 topic pub -r 10 /rps/player_gesture std_msgs/msg/String "{data: paper}"
```

**บน PC (WSL):** `arm start sim` แล้ว `arm rps random` / `arm rps topic` — มือเป็นแบบจำลองเสมอ
(กล้องกับมือจริงต่อฝั่ง Windows WSL มองไม่เห็น) ครั้งแรก build ก่อน:
`cd /mnt/c/Users/User/Desktop/Humanoi/ros2_ws && colcon build --symlink-install --packages-select humanoi_games`

## เรียกเล่นจากอย่างอื่น (ยังไม่ได้เลือกวิธี)

อะไรก็ได้ที่ส่งข้อความ `/rps/play` (`std_msgs/msg/Empty`) ได้:

| วิธี | ทำยังไง |
|---|---|
| พิมพ์คำสั่ง | `arm rps play` หรือ `ros2 topic pub --once /rps/play std_msgs/msg/Empty "{}"` |
| Foxglove | Publish panel → topic `/rps/play`, schema `std_msgs/msg/Empty`, ข้อความ `{}` → กดปุ่ม |
| สวิตช์รีโมท FlySky | ให้ `rc_arm_trigger` ส่ง `/rps/play` แทน `/arm/run` (ยังไม่ได้ทำ) |
| ปุ่มกด / เสียง / หน้าเว็บ | โหนดเล็กๆ ที่ publish `/rps/play` |

ฟังผล: `/rps/result` = `"<ท่าหุ่น>:<ท่าผู้เล่น|none>:<ผล>"` (ผล = `player_win` `robot_win` `draw` `no_player`
`stopped` `error:...`) · จังหวะระหว่างเล่น: `/rps/state` = `ready` `beat:1..3` `reveal:<ท่า>` `result:<ผล>` `idle`
— ไว้ต่อเสียงพูด "เป่า-ยิ้ง-ฉุบ" หรือจอแสดงผลในอนาคต

## ปรับแต่ง (พารามิเตอร์ของ rps_game)

| พารามิเตอร์ | ค่าเริ่ม | ความหมาย |
|---|---|---|
| `pump_deg` | 5.0 | ข้อ 1 ยกกี่องศา — 8° = 11.6 วินาที, 5° = 8.6, 4° = 7.7, 3° = 6.7 (มือยกราว 0.6 ซม./องศา) |
| `pump_count` | 3 | ขยับขึ้นลงกี่ครั้ง (launch arg ได้) |
| `pump_speed` / `pump_accel` | 0.20 / 0.17 | rad/s, rad/s² — เพดานคือเฟิร์มแวร์ (เร่งได้ 10°/s² = 0.1745) สั่งเกินก็ไม่เร็วขึ้น แขนแค่ตามหลัง |
| `auto_up` | true | เลือกทิศข้อ 1 ให้มือขึ้นเอง (false = ใช้เครื่องหมายของ pump_deg) |
| `hand_lead` | 0.4 | สั่งมือออกท่าก่อน "ฉุบ" กี่วินาที |
| `settle` / `player_window` | 0.2 / 1.2 | รอมือผู้เล่นนิ่ง / นับท่ากี่วินาที |
| `windup_gesture` | windup | ท่ามือตอนง้าง (กำหลวมๆ — ต่างจากค้อนที่กำสุด) |
| `min_votes` | 4 | ต้องเห็นมือกี่เฟรม |
| `max_draws` | 2 | เสมอแล้วเป่าใหม่ได้กี่ครั้ง |
| `react_hold` | 3.0 | ค้างท่าโชว์กี่วินาที |
| `victory_moves` | `victory_pose` | ท่าแขนตอนหุ่นชนะ — ชื่อท่าเรียงกันคั่นเว้นวรรค ไปทีละท่า (ท่าที่ไม่ได้สอนข้ามไป) |
| `lose_moves` | `victory_pose lose_pose` ×3 | ท่าแขนตอนหุ่นแพ้ — สลับสองท่า 3 รอบ |
| `show_speed` / `show_accel` | 0.22 / 0.17 | ท่าโชว์ที่ห่างกันไม่เกิน `show_fast_max_deg` (45°) ขยับด้วยเพดานเฟิร์มแวร์ (แกว่ง 39° ครั้งละ ~4.4 s) |
| `return_moves` | `move_readyP1 move_readyP2` | ท่าที่เดินผ่านก่อนเข้าท่าตั้ง (คั่นเว้นวรรค ต้องสอนครบ) |
| `near_deg` | 5.0 | ห่างท่าตั้งไม่เกินนี้ไปตรงๆ ได้ ไม่ต้องเดินผ่าน return_moves |
| `start_delay` | 1.0 | ถึงท่าตั้งแล้วรอกี่วินาทีก่อนเป่า |
| `replay_hold` | 0.8 | ต้องชูนิ้วชี้ค้างกี่วินาทีถึงจะเล่นใหม่ |
| `replay_timeout` | 60 | จบเกมแล้วรอนิ้วชี้กี่วินาที, 0 = รอตลอด (launch arg ได้) |
| `robot_choice` | random | บังคับท่าหุ่น rock/paper/scissors (ทดสอบ/โชว์ — launch arg ได้) |

ท่ามือ (องศาของ servo ต่อนิ้ว) แก้ที่ `humanoi_games/hand_poses.py` — ระบบเดียวกับเดโมของ Pollen
(แบ −35/35, กำ 90/−90) · ค้อน = กำสุด (`TIGHT`: มุมที่นิ้วชนฝ่ามือจาก find_limits ลบ 4°) · ตอนง้าง = `LOOSE` 30° · MiddlePos ยังเป็นค่าของเดโม (มือนี้ยังไม่ได้คาลิเบรต)

## ข้อควรรู้

- เส้นทางขยับไกลๆ ใช้โปรไฟล์นุ่ม (0.19 rad/s, 0.08 rad/s²) เหมือน `arm run` — จากท่าตั้งไปท่าโชว์ (~106° ที่ข้อ 1)
  ยังไปตรงๆ ถ้าอยากให้ขาไปเดินผ่านท่ากลางด้วย บอกได้ (ทำแบบ return_moves)

- ความเร็วเป่าถูกจำกัดที่เฟิร์มแวร์ (`JOINT_MAX_ACCEL` 10°/s² ทุกข้อใน AR4_ROS2_seq) เวลาลดตามรากที่สองของระยะ
  — เร็วกว่านี้ต้องเพิ่มค่าในเฟิร์มแวร์แล้วแฟลชใหม่ ระวังสายพาน J1 (แบกน้ำหนักแขนทั้งแขน เคยรูด)

- แขนสั่งตรงเข้า `left_arm_controller` เหมือน `arm run` — ไม่ผ่าน MoveIt ไม่เช็คการชน
- ความเร็ว/ความเร่งข้อ 1 ต่ำกว่าที่เฟิร์มแวร์ทำได้ (สายพาน J1 เคยรูดตอนแขนยื่นไกลแล้วกระชาก)
  — ลองครั้งแรกด้วยท่าตั้งที่แขนไม่ยื่นไกล
- โหนดมือปลดแรงบิดตอนปิด (นิ้วอ่อนลงเป็นกำ)
- แยกท่ามือผู้เล่นแบบนับนิ้วเหยียด (แบบเดียวกับ `Fun thing\robot_hand.py`) — มือหันข้าง/บังกันอาจอ่านผิด
  เกมโหวตหลายเฟรม ถ้าไม่ชัดจะนับเป็น "ไม่เห็นมือ"
