# โชว์หยิบกล่อง A → B (`arm show`)

คนคุมเล่นโชว์ **ทีละรอบด้วยรีโมท**: หุ่นหยิบกล่องที่โต๊ะ A ด้วยกล้อง → พับแขนถือกล่อง → รอคนคุมยืนยัน →
ฐานวิ่งไปโต๊ะ B → เข้าจอด → วางกล่อง → (ท่าโชว์) → กลับมาจอดที่ A · ใช้**แขนซ้าย** (แขนที่ calibrate กล้องแล้ว)

```
arm up left ab          เปิดทุกอย่างใน tmux (lidar ฐาน แขน player กล้อง โชว์) — เน็ตหลุดก็ไม่ตาย
SWB โยกลง               เริ่มรอบ · ยืนยันขั้นรอ · ทำต่อหลังหยุด / ลองใหม่หลังพัง
SWD โยกลง               หยุดทันที (ฐาน + แขนค้างท่า ไม่ตัดไฟ) · โยกอีกครั้งตอนหยุดอยู่ = จบรอบนี้
arm down                ปิดทั้งชุด
```

ต่อยอดจาก `arm mission` (docs/MISSION.md) — ความปลอดภัยชุดเดียวกันทั้งหมด (แขนต้องพับก่อนฐานวิ่ง · lidar
กันชนสองชั้น · รีโมทแย่งคุมได้ทุกเมื่อ) เพิ่ม: คุมทีละรอบ หยุดแล้วทำต่อได้ เส้นทางสอนหน้างาน เข้าจอดด้วย lidar บันทึกทุกรอบ

## หนึ่งรอบของโชว์ `ab`

| # | ขั้น | หุ่นทำอะไร | ถ้าพัง |
|---|---|---|---|
| 1 | `say` | ขึ้นข้อความให้คนดู (`/show/say`) | — |
| 2 | `pick: left` | ยกแขน `pick_ready_L` → หากล่องด้วยกล้อง → หยิบ | ลองใหม่เอง 1 ครั้ง แล้วรอคนคุม |
| 3 | `program` | แขนพับถือกล่อง `carry_L` | รอคนคุม |
| 4 | `confirm` | **รอ SWB** — คนคุมดูทางไป B ว่าโล่ง | — |
| 5 | `undock: A` | ถอยออกจากโต๊ะ A ไปจุดเริ่มเส้นทาง | รอคนคุม |
| 6 | `route: A_to_B` | วิ่งตามเส้นทางที่สอนไว้ | มีคนขวาง = หยุดรอ (เกิน 15 วิ รอคนคุม) |
| 7 | `dock: B` | เดินหน้าจน lidar เห็นโต๊ะ B ห่างเท่าที่จดไว้ | รอคนคุม |
| 8–10 | `program` `hand` `program` | วาง `place_B` → มือปล่อย → พับ `stow_L` | รอคนคุม |
| 11–13 | `say` `program: show_B` | ท่าโชว์ (ยังไม่มีโปรแกรม = ข้ามเอง) | ข้าม |
| 14–17 | `confirm` `undock: B` `route: B_to_A` `dock: A` | รอ SWB → กลับมาจอดที่ A | เหมือนขาไป |

จบรอบ: หุ่นจอดที่ A กล่องอยู่ที่ B — **คนยกกล่องกลับ A** ก่อนรอบถัดไป
(ซ้อมแล้วพลาดน้อย ค่อยเพิ่มโชว์ให้หุ่นหยิบกลับเอง — แก้ `shows.yaml` ได้เลย ไม่ต้อง build)

โชว์ซ้อมแยกส่วน: `arm show pick_only` (หยิบ-วางคืนที่ A ไม่ใช้ฐาน) · `arm show drive_only` (ฐานไป-กลับ แขนพับ)

## คุมโชว์

| ตอนนี้ | SWB / Enter | SWD / `s` | `q` |
|---|---|---|---|
| รอเริ่ม | เช็กระบบ → เริ่มรอบ | — | ออก |
| กำลังทำขั้น | — | **หยุดทันที** | หยุด + ออก |
| รอยืนยัน (`confirm`) | ไปต่อ | หยุด | ออก |
| หยุดอยู่ (หลัง SWD) | ทำขั้นนี้ต่อ (ฐานวิ่ง**เฉพาะระยะที่เหลือ**) | จบรอบนี้ | ออก |
| ขั้นพัง | ลองขั้นนี้ใหม่ | จบรอบนี้ | ออก |

- กดเริ่มรอบ = เช็กระบบก่อนทุกครั้ง (ท่า เส้นทาง ระยะจอด โปรแกรมที่ต้องเปิด odometry lidar โหมด Mega กล้องเห็นกล่อง)
  ไม่ผ่าน = ไม่ขยับ บอกว่าต้องแก้อะไร แก้แล้วโยก SWB ใหม่
- **จบกลางรอบ** → รอบใหม่เริ่มขั้นแรกเสมอ: ขับรีโมทพาหุ่นกลับมาจอดหน้าโต๊ะ A แขนว่าง/พับ กล่องวางที่ A ก่อน
- รีโมทแย่งคุมได้ทุกเมื่อ (ขยับคันโยก / ปลด SWA) — ฐานหยุด ขั้นนั้นพัง แล้วรอคนคุม (ยก SWA ขึ้นแล้วลง ปล่อยคันโยก → SWB = ลองใหม่)
- สวิตช์นับเฉพาะ "โยกลงจากบน" — ค้างลงไว้ไม่สั่งซ้ำ · เห็นหน้าจอโชว์: `tmux attach -t humanoi`

## ก่อนวันงาน (ที่ออฟฟิศ — ต้องมีเน็ต)

1. **ติดตั้ง tmux** (ครั้งเดียว): `sudo apt install tmux`
2. **เครือข่าย** — ตั้งตาม [เครือข่ายในงาน](#เครือข่ายในงาน) ให้ครบ แล้วลองทุกทางที่ออฟฟิศ
3. **ยึดกล้องให้แน่น** แล้ว calibrate กล้องใหม่: `arm tray-teach left` (ขยับกล้องแม้นิดเดียว = ต้องทำใหม่)
4. **สอนท่าแขนซ้าย** (ชื่อตาม `config/shows.yaml`):
   ```
   arm teach left pick_ready_L    แขนยกสูงเหนือกล่อง (ก่อนหยิบทุกครั้ง ทางไปไม่กวาดโดนกล่อง)
   arm teach left carry_L         ถือกล่องแนบตัว ศูนย์ถ่วงต่ำ ไม่ยื่นนอกฐาน (ฐานวิ่งท่านี้)
   arm teach left stow_L          แขนพับ มือว่าง (ฐานวิ่งท่านี้)
   arm teach left place_B         วางกล่องบนโต๊ะ B — สอนใหม่หน้างาน (ความสูงโต๊ะไม่รู้)
   ```
   เช็ก `arm j1-load left` — ท่าที่ใช้ทุกรอบควรไม่เกิน 100% (เกิน = J1 เสี่ยงรูด)
   ท่าโชว์หลังวาง: โปรแกรม `show_B` (`arm program show_B ...`) — ไม่มีก็เล่นได้
5. **ซ้อมทั้งชุดที่ออฟฟิศ** ด้วยโต๊ะสองตัว ตามขั้น [ตั้งหน้างาน](#ตั้งหน้างาน-12-ชั่วโมง) ทุกข้อ จับเวลาไว้
6. **ทดสอบตัวโปรแกรม** (ไม่ขยับของจริง ~8 นาที): `arm show test` — ต้องผ่านทุกข้อ

## ตั้งหน้างาน (1–2 ชั่วโมง)

| เวลา | ทำอะไร | คำสั่ง |
|---|---|---|
| 0:00 | วางโต๊ะ A / B · ทางระหว่างโต๊ะกว้าง ≥ 1 m · เปิดไฟหุ่น · เข้า Pi ได้ทางไหน | `bash ~/Humanoi/scripts/show-net.sh status` |
| 0:10 | calibrate แขนซ้าย (รอบแขนโล่ง ลำดับข้อที่ใช้ประจำ) | `arm calibrate left 6 5 4 1 2 3` |
| 0:20 | เปิดทุกอย่าง **ยกเว้นโชว์** | `arm up left none` |
| 0:25 | **จอดที่ A**: ขับรีโมทให้แขนหยิบกล่องได้สบาย → เช็กกล้องกับแขน → จดระยะจอด | `arm show verify left` · `arm show dock-save A` |
| 0:40 | **สอนเส้นทาง**: ถอยออกจาก A ~0.3 m (ตรงที่หมุนตัวได้ไม่ชนโต๊ะ) → บันทึก → ขับไป B ทีละขา → หยุด**หันหน้าเข้าโต๊ะ B ห่าง 0.45–0.7 m** → Enter | `arm drive back 0.3` · `arm show route-record A_to_B` |
| 0:55 | **จอดที่ B**: ขับรีโมทเดินหน้าช้าๆ จนถึงที่วางกล่อง → จดระยะ | `arm show dock-save B` |
| 1:00 | สอนท่าวางที่ B แล้วพับ | `arm moveit` → `arm teach left place_B` |
| 1:10 | เช็ก → ซ้อมฐาน 2 รอบ → ซ้อมหยิบ → ซ้อมเต็ม 2–3 รอบ | `arm show check ab` · `arm show drive_only` · `arm show pick_only` · `arm show ab` |
| 1:40 | เปิดโชว์จริง | `arm up left ab` |

ขากลับ `B_to_A` ได้ให้เองตอนสอน `A_to_B` (หมุน 180° → ย้อนขา → หมุน 180°) · ระยะถอยออกจากโต๊ะ (`undock`)
จดให้เองด้วย = ตอนเริ่มเส้นทางห่างโต๊ะ A เท่าไหร่ / ตอนจบห่างโต๊ะ B เท่าไหร่ — ขากลับจึงเริ่มตรงจุดเดิมพอดี

### กติกาเส้นทาง

- **ขับทีละอย่าง**: วิ่งตรง (หน้า / หลัง / สไลด์) **หรือ** หมุนอยู่กับที่ — หยุดนิ่ง ~1 วิ = จบขา
  โปรแกรมพิมพ์ขาที่จดได้ทุกครั้ง · `u` = ลบขาล่าสุด ขับใหม่ · `q` = ยกเลิก
  ขาไหนขึ้น ⚠ (หัวหมุนระหว่างวิ่งตรง / เบี้ยวข้างมาก) = ลบแล้วขับใหม่
- **ใช้เดินหน้ากับหมุน** เป็นหลัก — ฐานถอยหลังยังวิ่งไม่ตรง (ขากลับสร้างจากเดินหน้าทั้งหมด)
- **จบเส้นทางห่างโต๊ะ 0.45–0.7 m หันหน้าเข้าโต๊ะ** — ใกล้กว่า 0.35 m กันชนจะหยุดรอจนหมดเวลา ·
  ไกลกว่า 0.6 m + ระยะจอด ขั้น dock ไม่ยอมวิ่ง (กันวิ่งเลยถ้า lidar เห็นผิดที่)
- ระยะยาว / มีหลายขา = คลาดสะสม (ขาละ ~1–3 cm, หมุนละ ~1–3°) — ขั้น dock แก้ระยะหน้า-หลังให้ แต่ซ้าย-ขวาไม่แก้
  วางโต๊ะให้ทางสั้นและตรงที่สุด
- **หน้าโต๊ะต้องมีของที่ lidar เห็น** ที่ความสูง 23.5 cm (ระดับ lidar) — โต๊ะขาโปร่ง lidar เห็นแค่ขาโต๊ะ ·
  ใช้ผ้าคลุมโต๊ะถึงพื้น หรือวางกล่อง / แผ่นป้ายหน้าโต๊ะ
- พิมพ์เส้นทางเองก็ได้ (วัดด้วยตลับเมตร): `arm show route-set A_to_B "turn 90, forward 1.5, turn -90"`
  (ไม่มีระยะถอยจาก route-record = undock ถอยเท่าที่ dock เข้าไป / 0.25 m)
- ตั้งระยะจอดเอง: `arm show dock-set B 0.12` · แก้มือได้ที่ `config/routes.yaml` — โชว์อ่านไฟล์ใหม่ทุกรอบ

## เครือข่ายในงาน

**โชว์ไม่ต้องใช้เน็ตเลย** — เปิด `arm up` แล้วคุมด้วยรีโมทล้วนได้ทั้งวัน เน็ตจำเป็นแค่ตอนตั้งหน้างาน / ดูหน้าจอ / แก้ปัญหา
Pi Connect ต้องมีอินเทอร์เน็ต — ในงานใช้ทางอื่นตามลำดับ:

| ลำดับ | ทาง | เข้า Pi | ต้องเตรียม |
|---|---|---|---|
| 1 | **เราเตอร์พกพา (2.4 GHz)** ไม่ต้องมีอินเทอร์เน็ต | `ssh eitlaser@EIT-Raspberry-Pi-5.local` (หรือ IP จากหน้าเราเตอร์) | `show-net.sh router "<SSID>"` — Pi ต่อตัวนี้ก่อน WiFi อื่น |
| 2 | **hotspot ของ Pi เอง** (เปิดเครื่อง 90 วิแล้วหา WiFi ที่รู้จักไม่เจอ = เปิดเอง) | WiFi `Humanoi-Show` → `ssh eitlaser@10.42.0.1` | `show-net.sh hotspot-setup` + `show-net.sh fallback-install` |
| 3 | **สาย LAN ตรงโน้ตบุ๊ก** | `ssh eitlaser@169.254.77.1` (รอ ~1 นาทีหลังเสียบ) | `show-net.sh direct-setup` |
| 4 | จอ HDMI + คีย์บอร์ด ที่ Pi | — | พกจอ / สาย micro-HDMI |

สคริปต์ `scripts/show-net.sh` (รันบน Pi นอก container — ถามรหัส sudo และรหัส WiFi เอง ไม่ขึ้นจอ):
```
bash ~/Humanoi/scripts/show-net.sh status
bash ~/Humanoi/scripts/show-net.sh router "ชื่อWiFiเราเตอร์"
bash ~/Humanoi/scripts/show-net.sh hotspot-setup
bash ~/Humanoi/scripts/show-net.sh fallback-install
bash ~/Humanoi/scripts/show-net.sh direct-setup
```
- เราเตอร์พกพาเป็น 2.4 GHz — Pi 5 ต่อได้ปกติ · ในงานคลื่น 2.4 GHz แน่นมาก: วางเราเตอร์ใกล้หุ่น ตั้ง channel 1 / 6 / 11 ตัวที่ว่าง
- hotspot เปิด = Pi หลุดจาก WiFi อื่น (ใช้ wlan0 ตัวเดียวกัน) · ปิด: `show-net.sh hotspot off`
- `direct-setup` แล้ว สาย LAN เข้าเราเตอร์จะไม่ได้ IP จากเราเตอร์ — เลิกใช้: `show-net.sh direct-remove`
- **เปิดโชว์ด้วย `arm up` เสมอ** — เปิดในหน้าต่าง SSH ธรรมดาแล้วเน็ตหลุด = หน้าต่างตาย (และโปรแกรมอาจค้างอยู่เบื้องหลัง
  คุมต่อไม่ได้) · ใน tmux เน็ตหลุดไม่เป็นไร ต่อใหม่แล้ว `tmux attach -t humanoi`

## ถ้ามีปัญหา

| อาการ | ทำ |
|---|---|
| เช็กระบบไม่ผ่าน | อ่านรายการ ✗ — ส่วนใหญ่คือหน้าต่างไหนปิดไป (`tmux attach -t humanoi` ดูทีละหน้าต่าง Ctrl+B แล้ว n) |
| กล้องไม่เห็นกล่อง | ป้ายต้องเห็นทั้งแผ่น ไม่สะท้อนไฟ · ขยับกล่องเข้ากลางภาพ · SWB ลองใหม่ |
| หยิบพลาด / ปลายนิ้วไม่ตรงหูกล่อง | `arm show verify left` — คลาดเกิน ~5 mm = กล้องขยับ: `arm tray-teach left` |
| ฐานหยุดรอกลางทาง | lidar เห็นของในทาง (คน / ขอบโต๊ะ) — ทางโล่งแล้วไปต่อเอง · เกิน 15 วิ = รอ SWB |
| dock: "ไม่เห็นอะไรข้างหน้า" | เส้นทางจบไกล / หันเบี้ยว / หน้าโต๊ะ lidar มองไม่เห็น — ขับรีโมทจัดให้หันเข้าโต๊ะแล้ว SWB ลองใหม่ |
| จอดที่ B เบี้ยวซ้าย-ขวาทุกรอบ | สอนเส้นทางใหม่ (ขาสั้นลง หมุนให้ตรง) · จูนล้อ `arm wheel-tune` |
| J1 รูด / แขนชน | SWD → `arm broke slipped left j1` → `arm recal left 1` — สั่งใน tmux (`tmux attach -t humanoi` แล้ว Ctrl+B c = หน้าต่างใหม่) เพราะตัวคุมแขนจะเปิดค้างในหน้าต่างนั้น |
| Mega โหมดไม่ใช่ ROS | ยก SWA ขึ้นแล้วลง ปล่อยคันโยก |
| ต้องดับไฟแขน | ประคองแขนก่อน — ตัดไฟแล้ว J1 ร่วง · เปิดใหม่ต้อง calibrate |

## บันทึกและสถานะ

- ทุกรอบเขียนลง `~/Humanoi/ros2_ws/arm_logs/show-YYYY-MM-DD.jsonl`: รอบที่ เวลา ผล (`done` / `ended` / `quit`)
  แต่ละขั้นทำกี่ครั้ง โดนหยุดกี่หน ใช้เวลาเท่าไหร่ ข้อผิดพลาด — ไว้ดูหลังงานว่าขั้นไหนพังบ่อย
- `/show/state` (JSON ทุก 1 วิ): `phase` (idle / running / confirm / paused / error) รอบ ขั้น ข้อความล่าสุด — ต่อจอแสดงผลทีหลังได้
- `/show/say` (String): ข้อความจากขั้น `say` · `/show/cmd` (String): `go` / `stop` / `quit` สั่งจากโปรแกรมอื่นได้

## ขั้นและตัวเลือก (`config/shows.yaml`)

ขั้นของ mission (`confirm` `program` `hand` `pick` `place_back` `move` `wait`) + ขั้นของโชว์:

| ขั้น | ตัวอย่าง | ทำอะไร |
|---|---|---|
| `say` | `say: "วางกล่องเรียบร้อย"` | ข้อความให้คนดู |
| `route` | `route: A_to_B` | วิ่งตามเส้นทางใน `routes.yaml` |
| `dock` | `dock: B` · `dock: {front: 0.12}` | เดินหน้าจนข้างหน้าห่างเท่านี้ (m จากขอบหน้าตัวหุ่น) |
| `undock` | `undock: B` · `undock: 0.3` | ถอยออกจากโต๊ะกลับปลายเส้นทาง / ถอยตามระยะ |

ตัวเลือกใส่ได้ทุกขั้น: `retry: 2` (พังแล้วลองใหม่เองกี่ครั้ง) · `optional: true` (พังแล้วข้าม) ·
`prep: "@left:pick_ready_L"` (เล่นก่อนทุกครั้งที่ทำขั้นนั้น) · `note:` (หมายเหตุ ไม่มีผล)

`stow:` = ท่าที่ฐานวิ่งได้ — แขนขวาตั้ง `skip` ไว้ระหว่างซ่อม (เช็กไม่ได้ ต้องพับ / รองไว้เอง) ·
ซ่อมเสร็จสอน `arm teach right stow_R` แล้วเปลี่ยนเป็น `right: [stow_R]`

## ทดสอบโดยไม่ใช้ของจริง

`arm show test` (หรือ `bash tools/show_sim/run_show_tests.sh` ใน WSL) — แขนจำลอง + ฐานจำลอง (`show_mock`:
odometry, lidar ยิงลำแสงใส่โต๊ะในโลกจำลอง `tools/show_sim/world.yaml`, ตัวกันชน lidar ตัวจริง, รีโมทจำลอง) ใช้
`ROS_DOMAIN_ID` แยก ไม่กวนระบบจริงที่เปิดอยู่ · ทดสอบ: ครบรอบกลับถึง A · กล้องหาไม่เจอ → ลองใหม่ ·
คนเดินตัดหน้า · SWD แล้วทำต่อ (วิ่งแค่ระยะที่เหลือ) · SWD สองครั้ง · สอนเส้นทางด้วยการขับ

เล่นเองกับของจำลอง (3 หน้าต่าง ใน container หรือ WSL):
```
ros2 launch ar_dual dual_hardware.launch.py left_hw:=mock right_hw:=mock   (+ arm_program, amazinghand_node dry_run)
ros2 run humanoi_mission show_mock --ros-args -p world_file:=tools/show_sim/world.yaml
ros2 run humanoi_mission show run ab --ros-args -p mock:=true
ros2 topic pub --once /show_mock/cmd std_msgs/msg/String "data: 'obstacle front 0.5'"   (rc B=D · pick fail 2 · reset)
```
