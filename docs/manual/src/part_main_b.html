ฐานล้อ

ฐานเป็นล้อ mecanum สี่ล้อ แต่ละล้อมีมอเตอร์ 24V ของตัวเอง ทิศของแต่ละล้อสั่งด้วย relay สองตัว (เดินหน้า/ถอย) ส่วนความเร็วตั้งด้วยลูกบิด HW-687 ของแต่ละล้อ — โปรแกรมคุมได้แค่ทิศ เดินหน้า ถอย หรือหยุด จึงต้องจูนลูกบิดให้สี่ล้อหมุนเท่ากัน ฐานถึงจะวิ่งตรง ที่ความเร็วปัจจุบัน (~50 รอบ/นาที) ฐานวิ่งราว 0.38 m/s ช้ากว่าคนเดินประมาณ 3 เท่า

เฟิร์มแวร์ Mega

จูนความเร็วล้อ

ลูกบิด HW-687 ตั้งความเร็วของแต่ละล้อ สี่ล้อต้องหมุนเท่ากันฐานถึงจะวิ่งตรง arm wheel-tune หมุนทุกล้อค้างไว้ แล้วแสดงรอบต่อนาทีทุกวินาที พร้อมบอกว่าลูกบิดล้อไหนต้อง เพิ่ม หรือ ลด หมุนลูกบิดทีละนิดจนทุกล้อขึ้น ✓ (ต่างไม่เกิน ±1.5%)

arm wheel-tune
# ยกล้อลอย หมุนค้างจนกด Ctrl+C · ใส่ตัวเลขได้ เช่น arm wheel-tune 50 = เทียบกับ 50 rpm

เดินหน้ากับถอยหลังเร็วไม่เท่ากัน

มอเตอร์แปรงถ่านมักหมุนสองทิศเร็วไม่เท่ากัน แต่ลูกบิดตัวเดียวคุมทั้งสองทิศ สิ่งที่สำคัญคือสี่ล้อในทิศเดียวกันเร็วเท่ากัน (ฐานถอยช้ากว่าเดินหน้าได้ ขอแค่ถอยตรง) arm wheel-tune both วัดเดินหน้าและถอยหลังครั้งเดียว แล้วบอกว่าแต่ละล้อต้องตั้งเดินหน้าเท่าไร ให้ทิศถอยสมดุลไปด้วย จากนั้นหมุนเดินหน้าค้างให้จูนตามเป้าแยกล้อ ถ้าทุกล้อต่างพอๆ กันจะขึ้น "ไม่ต้องปรับลูกบิด"

arm wheel-tune both

บนพื้น (ล้อรับน้ำหนัก ความเร็วเปลี่ยนเล็กน้อย) ใช้แบบจำกัดเวลา ไม่งั้นฐานจะวิ่งไปจนกด Ctrl+C:

arm wheel-tune 3s
# เดินหน้า 3 วิแล้วหยุดเอง (~1 m) · arm wheel-tune both 3s = ไป 3 วิ กลับ 3 วิ
หมายเหตุ สถานะ 29 ต.ค.: จูนทิศเดินหน้าสมดุลแล้ว ทิศถอยยังต่างกันมาก — วางเส้นทางให้ฐานเดินหน้าเป็นหลัก

สั่งฐานวิ่งตามระยะ

arm drive สั่งฐานวิ่งเป็นระยะหรือหมุนเป็นมุม แล้วหยุดเองโดยวัดจาก encoder ระหว่างทางมี lidar กันชน (ต้องเปิด arm base และ arm lidar)

arm drive forward 1.0
# forward / back / left / right เป็นเมตร · turn 90 เป็นองศา (บวก = หมุนซ้าย)

จบแล้วบอกผล เช่น เดินหน้า 0.512 m จาก 0.500 m (เลย 1.2 cm) · เบี้ยวข้าง +0.8 cm · หัวหมุน +0.4° ถ้าเลยเป้าทุกครั้ง (ล้อไหลหลังตัด relay) ให้เพิ่ม base.stop_early ถ้าเบี้ยวมาก ให้จูนลูกบิดก่อน

ระวัง ระหว่าง arm drive ขยับคันโยก / โยก SWA ขึ้น / Ctrl+C = หยุดทันที ของขวางทาง = หยุดรอจนโล่ง (ไม่อ้อม)

เปิด lidar

arm lidar

เปิดค้างไว้ ข้อมูลออกที่ /scan_raw แล้วผ่านตัวกรอง scan_mask ที่ตัดจุดที่ตกบนตัวหุ่นเอง (เช่นเสา) ออก ส่งต่อเป็น /scan ให้กันชนและแผนที่

เช็กการติดตั้ง (arm lidar-check)

ทำครั้งแรก และทุกครั้งที่ถอดหรือขยับ lidar โปรแกรมเช็กสองเรื่อง: lidar หันตรงหน้าฐานหรือเบี้ยว และข้อมูลซ้าย/ขวาถูกด้านไหม (ถ้ากลับด้าน กันชนจะห้ามผิดข้าง)

  1. เปิด arm lidar ไว้ แล้วอีกหน้าต่าง 
    arm lidar-check
  2. วางของแคบๆ ตั้งตรง (ขวด กระป๋อง ขาเก้าอี้ กว้าง 3–10 cm) หน้าหุ่น ห่างราว 1 m ตรงแนวกลาง — วัดจากมุมหน้าซ้ายและมุมหน้าขวาของแผ่นฐานถึงของ ได้เท่ากัน รอบของโล่ง 40 cm
  3. กด Enter แล้วเดินออกห่างหุ่นเกิน 1.5 m ภายใน 5 วิ (ขาคนจะถูกนับเป็นของ) → โปรแกรมบอกมุมเบี้ยว และถามระยะจากตลับเมตรไว้เทียบ (ข้ามได้)
  4. ย้ายของไปวางข้างซ้ายของหุ่น (ฝั่งแขนซ้าย) ห่างข้างฐาน 30–50 cm กด Enter แล้วเดินออก → ต้องขึ้น "ซ้าย/ขวาถูกด้าน"
  5. ตอบ y บันทึกมุม → ปิด/เปิด arm lidar
ระวัง ถ้าขึ้น "ข้อมูล lidar กลับด้าน" ห้ามใช้กันชนจนกว่าจะแก้ laser_scan_dir ใน humanoi_description/launch/lidar.launch.py แล้วเช็กใหม่

ทำแผนที่

arm map ทำแผนที่จาก lidar อย่างเดียว (เดาการเคลื่อนที่จากการเลื่อนของภาพสแกน ไม่ต้องใช้ encoder) คนคุมขับฐานด้วยรีโมท คำสั่งนี้เปิด lidar ให้เอง — ปิด arm lidar ก่อน

  1. arm map
  2. บน PC เปิด Foxglove ต่อ ws://192.168.1.74:8765 (หรือ IP ที่หน้าต่างบอก) · panel 3D · Display frame = map · เปิด /map และ /scan
  3. ขับช้าๆ ให้ทั่วพื้นที่: วิ่งตรงเป็นช่วงๆ สไลด์แทนการหมุน หมุนทีละน้อย (หมุนเร็ว = แผนที่เละ) เลียบผนัง แล้ววนกลับจุดเริ่มให้แผนที่ปิดวง
  4. ทำตอนคนน้อย (คนเดินผ่าน = จุดเปื้อน)

ระบบกันชน

กันชน lidar ทำให้ฐานไม่ขับเข้าหาของ ไม่ว่าคำสั่งจะมาจากรีโมทหรือจาก ROS การตัดสินใจขั้นสุดท้ายอยู่ที่ Mega ซึ่งทำงานแม้ Pi ค้าง ส่วน Pi เป็นคนดู lidar แล้วบอก Mega ว่าทิศไหนมีของ

ทำงานยังไง

  1. relay_bridge (เปิดด้วย arm base) อ่าน /scan แล้วดูทุกทิศว่ามีจุดอยู่ในกรอบทางที่จะไปไหม — เดินหน้า/ถอย/สไลด์: กรอบกว้างกว่าตัวหุ่นข้างละ 5 cm ยื่นออกไป 30 cm จากขอบตัว · หมุน: วงที่มุมตัวหุ่นกวาด + 5 cm
  2. ส่งให้ Mega ทุก 50 ms ว่าทิศไหนห้าม
  3. Mega ดูว่าคำสั่งล้อตอนนั้นพาตัวหุ่นไปทิศไหน — ไปทิศที่ห้าม = หยุดทุกล้อทันที ถอยหนีหรือสไลด์หนีของยังทำได้เสมอ
  4. ของต้องออกไปไกลเกิน 35 cm ต่อเนื่อง 0.5 วิ ถึงปลด (กัน relay กระพริบตอนของอยู่ตรงขอบ)

สถานการณ์Mega ทำอะไร
Mega เพิ่งบูต ยังไม่ได้ยิน Piไม่กัน — ขับด้วยรีโมทอย่างเดียวได้เหมือนเดิม

อยากขับต่อตอน LOST (ไม่มี lidar)โยก SWA ขึ้นแล้วลงหนึ่งครั้ง → ขับได้โดยไม่มีกันชน จนกว่า Pi จะกลับมาส่ง
arm base noguardไม่กัน — ใช้ตอนยกล้อจูน/ทดสอบเท่านั้น

ดูสถานะ: หน้าต่าง arm base บอก กันชน: ห้าม F---T ทุกครั้งที่เปลี่ยน (F หน้า B หลัง L ซ้าย R ขวา T หมุน) Mega รายงาน GUARD:ON … / GUARD:HOLD … (กำลังหยุดล้อไว้) / GUARD:FREE / GUARD:LOST / GUARD:OFF

ทดสอบบนหุ่นจริง

  1. ยกล้อ: arm base noguard → arm wheel-check ยังผ่านเหมือนเดิม
  2. arm base (ไม่เปิด lidar) → ดันคันโยก ล้อต้องไม่หมุน · หน้าต่าง base ขึ้น "ไม่มีค่า lidar"
  3. วางพื้น เปิด arm lidar + arm base → คนยืนห่าง 1.5 m ขับรีโมทเข้าหาช้าๆ → ต้องหยุดเอง วัดระยะที่เหลือจริง แล้วปรับ guard.stop_dist
  4. ตอนหยุดอยู่ ดึงคันโยกถอย → ต้องถอยได้
  5. คนเดินตัดหน้าตอนวิ่ง → หยุด · คนเดินพ้น → ปล่อยคันโยกแล้วดันใหม่ วิ่งต่อได้
  6. ถอด USB lidar ตอนวิ่ง → หยุดใน ~0.5 วิ · Ctrl+C arm base → รีโมทขับไม่ได้ → โยก SWA ขึ้น-ลง → ขับได้

ก่อนแฟลช Mega ทุกครั้งที่แก้เฟิร์มแวร์หรือ relay_bridge ให้รันชุดทดสอบ — มันคอมไพล์เฟิร์มแวร์ Mega ตัวจริงเป็นโปรแกรม Linux ต่อกับ relay_bridge ตัวจริงผ่านพอร์ตจำลอง ใส่ lidar และรีโมทปลอม แล้วเล่นทุกกรณีในตารางข้างบน (ต้องมี g++ และ ROS 2 Jazzy)

bash tools/mega_sim/run_tests.sh
# ผลที่ถูก: 37/37 ผ่าน

ข้อจำกัด

  • lidar เห็นระนาบเดียว สูง 23.5 cm — เห็นหน้าแข้งคน ขาโต๊ะ ผนัง แต่ไม่เห็นของเตี้ยกว่า (กล่อง/สายบนพื้น เด็กนั่งพื้น) และขอบโต๊ะ/ป้ายที่ยื่นเหนือระนาบ
  • คนยืน: lidar เห็นหน้าแข้ง แต่ปลายเท้ายื่นมาหาหุ่นอีก ~15–20 cm หยุดที่ 30 cm จากหน้าแข้ง = เหลือ ~10 cm ถึงปลายเท้า ระยะไหลหลังตัด relay ต้องน้อยกว่านั้น
  • โต๊ะที่จุดวางกล่อง: กันชนไม่ให้ฐานเข้าใกล้ขาโต๊ะเกิน 30 cm — ระยะจอดที่จุด B ต้องเผื่อ
  • ด้านหลังมีมุมเงาเสา — ถอยหลังในมุมนั้นไม่ถูกกัน
  • กรอบคิดจากขนาดฐาน 53 × 42.5 cm — ถ้าแขนพับแล้วยื่นเลยฐาน ต้องขยาย guard.footprint ต้องเช็ก: แขนพับแล้วยื่นเลยขอบฐานไหม
  • ยังไม่มีปุ่ม E-stop ตัดไฟมอเตอร์

ภารกิจ A → B

ภารกิจคือลำดับขั้นที่หุ่นทำต่อกันเอง เขียนไว้ในไฟล์ ros2_ws/src/humanoi_mission/config/missions.yaml ภารกิจหลักของงานจัดแสดงชื่อ demo_ab: หยิบกล่องที่ A ด้วยกล้อง พับแขน รอคนยืนยันจากรีโมท ฐานวิ่งไป B วาง แล้วกลับ คนคุมถือรีโมทตลอด หยุดได้ทุกเมื่อ

ความปลอดภัยในภารกิจ

ชั้นทำงานยังไง
รอยืนยันก่อนฐานวิ่งขั้น confirm = รอคนคุมโยก SWB (หรือ Enter ที่หน้าต่างภารกิจ) — ใส่ไว้ก่อนทุกช่วงที่ฐานวิ่ง
แขนพับก่อนฐานวิ่งฐานไม่ยอมวิ่งถ้าแขนไม่อยู่ท่าในรายการ stow (ห่างไม่เกิน 5° ทุกข้อ)
กันชนของในทางใกล้กว่า 35 cm = หยุดรอ · เกิน 15 วิ = เลิกภารกิจ · Mega กันซ้ำที่ 30 cm
หยุดฉุกเฉินโยก SWD หรือ Ctrl+C = หยุดฐาน + หยุดแขน (ค้างท่า) + จบภารกิจ
รีโมทแย่งคุมขยับคันโยก / ปลด SWA / รีโมทดับ = Mega ตัดฐานเอง ภารกิจหยุดตาม

เตรียมครั้งแรก

  1. สอนท่าแขน ที่ภารกิจใช้ (เปลี่ยนชื่อในไฟล์ได้): 
    arm teach left carry_L
# แขนซ้ายพับเข้าหาตัว ถือกล่อง — ศูนย์ถ่วงต่ำ ไม่ยื่นนอกฐาน
    arm teach left stow_L
# แขนซ้ายพับ มือว่าง
    arm teach right stow_R
# แขนขวาพับ
    arm teach left place_B
# แขนซ้ายวางกล่องบนโต๊ะ B (จอดฐานที่ B ก่อนแล้วจัดท่า)
  2. ลองฐานวิ่งตามระยะ ทีละคำสั่ง ดูว่าไปได้จริงเท่าไร (บท ฐานล้อ)
  3. วัดเส้นทางจริง A → B ในงาน แล้วแก้ระยะ/มุมในขั้น move ของ demo_ab — วางเส้นทางให้ฐานเดินหน้าเป็นหลัก (ทิศถอยยังจูนไม่สมดุล) ในไฟล์ตัวอย่างตอนนี้ ขากลับยังเป็นการถอย (back: 0.5 → turn: -90 → back: 1.0) ถ้าลองแล้วถอยเบี้ยว ให้เปลี่ยนขากลับเป็นหมุนกลับหัวแล้วเดินหน้าแทน
  4. ซ้อมทีละส่วน: arm mission test_pick (หยิบ-วางคืน ไม่ใช้ฐาน) และ arm mission test_drive (ฐานไป-กลับ 0.5 m)
