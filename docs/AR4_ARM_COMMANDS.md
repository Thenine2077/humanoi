# คู่มือคำสั่งแขน AR4 สองแขน บน Raspberry Pi

หุ่นมีแขน AR4 สองตัวบนเสา เรียกตามด้านเมื่อ**มองจากตัวหุ่น**:

- **left** = แขน 1 (แขนซ้าย) — พิมพ์ `left`, `l`, `1` หรือ `ซ้าย` ก็ได้
- **right** = แขน 2 (แขนขวา) — พิมพ์ `right`, `r`, `2` หรือ `ขวา` ก็ได้

ทุกคำสั่งพิมพ์ใน **Terminal ของ Pi** (นอก container) — เปิดได้ 2 ทาง:

- **Raspberry Pi Connect** → Terminal บนเดสก์ท็อป Pi (ต้องใช้ทางนี้ถ้าจะเปิด MoveIt)
- **จาก PC:** `ssh eitlaser@192.168.1.68`

พิมพ์ `arm help` เพื่อดูรายการคำสั่งทั้งหมดได้ตลอด

> **ห้ามถอดหรือเสียบสาย USB ของแขนขณะไฟแขนเปิด** — ปิดไฟแขนก่อนทุกครั้ง
> (Pi 5 ตัวแรกเสียหลังถอดสาย Teensy ตอนไฟแขนเปิดอยู่ เมื่อ 19 ต.ค. 2026)
>
> **หยุดฉุกเฉิน:** ปิดสวิตช์ไฟแขน (เร็วที่สุด) — `arm stop` และปุ่ม Stop ใน RViz เป็นการหยุดทางซอฟต์แวร์ ใช้แทนไม่ได้

## 0. ตั้งค่าครั้งแรก (Pi ใหม่ / เปลี่ยนบอร์ด / แฟลชเฟิร์มแวร์ใหม่)

ทำครั้งเดียว — ชื่อแขนและทิศมอเตอร์เก็บอยู่ในบอร์ด Teensy ของแต่ละแขน (เฟิร์มแวร์ AR4_ROS2_seq v2)
ย้ายสาย USB ไปช่องไหนของ Pi ก็หาเจอเอง

1. **เช็กไฟย้อนก่อนต่อแขนเข้า Pi ใหม่:** เปิดไฟแขน ยังไม่เสียบ USB เข้า Pi แล้ววัดแรงดันที่หัว USB-A ปลายสาย
   ระหว่างขา 5V (ขาริม) กับ GND (ขาริมอีกข้าง) ทุกเส้น (Teensy + Nano ทั้งสองแขน) — **ต้องได้ 0V**
   ถ้าได้ ~5V ห้ามเสียบ แขนจ่ายไฟย้อนเข้า Pi ต้องแก้ก่อน (หรือใส่ USB isolator คั่น)
2. ปิดไฟแขน → เสียบ USB ทุกเส้นเข้า Pi → เปิดไฟแขน
3. `arm ports` — ดูบอร์ด Teensy ทุกตัว: พอร์ต, เฟิร์มแวร์ (`seq2`), ชื่อแขน, ข้อที่ตั้งกลับทิศ
4. `arm identify` — ตั้งชื่อบอร์ด:
   - ข้อ 6 (ข้อมือ) ของแต่ละบอร์ดจะหมุนไป-กลับ 10° ทีละบอร์ด
   - ดูว่าแขนไหนขยับ แล้วตอบ `l` (ซ้าย) / `r` (ขวา) / `a` (ขยับอีกที) / `s` (ข้าม)
   - จบแล้วขึ้น `left=... right=...` = ใช้ได้ · เช็กซ้ำทีหลังได้ด้วย `arm identify left` (หมุนเฉพาะแขนนั้น)
   - ไม่เห็นอะไรขยับ = ไฟแขนปิดอยู่
5. **หาลำดับ calibrate ที่มือไม่ชน** (หัวข้อ 4) — ไล่ทีละข้อ `arm calibrate left 6`, `arm calibrate left 5`, ...
   ได้ลำดับที่ปลอดภัยแล้วตั้งเป็นค่าเริ่ม `LEFT_CAL_ORDER` / `RIGHT_CAL_ORDER` ใน `~/Humanoi/scripts/arm.sh`
6. ข้อไหน calibrate แล้วขึ้น `✗ ... FAIL` = มอเตอร์ข้อนั้นหมุนกลับด้าน → `arm dir <แขน> <6 หลัก>`
   เช่น `arm dir right 000010` (J5 กลับทิศ) แล้ว calibrate ข้อนั้นใหม่
7. หลัง calibrate ครั้งแรก แขนอยู่ท่าพัก → `arm start` แล้วบันทึกท่าพักของแขนที่ยังไม่มี: `arm teach right rest`

## 1. เริ่มใช้งาน

คำสั่งที่ "เปิดค้าง" ต้องใช้ **หน้าต่างละคำสั่ง** และห้ามปิดหน้าต่างระหว่างใช้งาน

| ขั้น | หน้าต่าง | คำสั่ง | หมายเหตุ |
|---|---|---|---|
| 0 | ไหนก็ได้ | `arm status` | ดูว่าอะไรเปิดอยู่ + บอร์ดแขน — ระบบแขนต้องเป็น ✗ ก่อนเริ่ม |
| 1 | หน้าต่าง 1 | `arm calibrate left` แล้ว `arm calibrate right` | **เฉพาะเมื่อจำเป็น** (หัวข้อ 4) — ทีละแขน จบเองเมื่อเสร็จ |
| 2 | หน้าต่าง 1 | `arm start` | เปิดระบบสองแขน — **เปิดค้างไว้** (`arm start left` = แขนซ้ายจริง แขนขวาจำลอง) |
| 3 | หน้าต่าง 2 | `arm player` | เปิดตัวเล่นโปรแกรม — **เปิดค้างไว้** (ความเร็วเริ่มต้น 0.19) |
| 4 | หน้าต่าง 3 (บนเดสก์ท็อป Pi) | `arm moveit` | MoveIt + RViz สองแขน — เฉพาะตอนจัดท่า (หัวข้อ 2) |

### ลำดับเต็ม แบบต้อง calibrate

```text
หน้าต่าง 1:  arm calibrate left    → อ่านคำเตือน → Enter → รอจนขึ้น "calibrate ครบตามที่สั่งแล้ว"
หน้าต่าง 1:  arm calibrate right   → เหมือนกัน
หน้าต่าง 1:  arm start             → เปิดค้างไว้
หน้าต่าง 2:  arm player            → เปิดค้างไว้
หน้าต่าง 3:  arm run <โปรแกรม>     → ทดสอบ (หรือ arm moveit บนเดสก์ท็อป Pi ถ้าจะจัดท่า)
```

### ลำดับเต็ม แบบไม่ต้อง calibrate

```text
หน้าต่าง 1:  arm start
หน้าต่าง 2:  arm player
หน้าต่าง 3:  arm run <โปรแกรม>
```

`arm start` หาพอร์ตของแต่ละแขนเองจากชื่อในบอร์ด แล้วแสดงว่าใช้พอร์ตไหน (`ซ้าย=real @ ... · ขวา=real @ ...`)

## 2. สอนท่า / สร้างโปรแกรม / เล่น (หน้าต่างไหนก็ได้)

| ทำอะไร | คำสั่ง (ตัวอย่าง) |
|---|---|
| บันทึกท่าปัจจุบันของแขนหนึ่ง | `arm teach left pick_above` |
| สร้างโปรแกรมสองแขน | `arm program pick2 rest/rest act1/act1 act2/- wait=1.0 rest/rest` |
| ดูโปรแกรมเป็นตาราง | `arm show pick2` |
| ดูท่าทุกแขนและโปรแกรมทั้งหมด | `arm list` |
| เล่นโปรแกรม (รอจนจบแล้วบอกผล ✓/✗) | `arm run pick2` |
| หยุดโปรแกรมกลางคัน (ทุกแขน) | `arm stop` |
| พาแขนเดียวไปท่าเดียว | `arm goto right pick_above` |
| ลบท่า (ต้องไม่มีโปรแกรมไหนใช้อยู่) | `arm delete left pick_above` |
| ลบโปรแกรม (ท่าในโปรแกรมยังอยู่) | `arm delete-program pick2` |

ท่าเก็บ**แยกตามแขน** — ชื่อท่าซ้ำกันข้ามแขนได้ (เช่น `rest` ของแขนซ้ายกับ `rest` ของแขนขวาเป็นคนละท่า)
ตั้งชื่อท่าและโปรแกรมเป็นภาษาอังกฤษหรือตัวเลข

### เขียนโปรแกรมสองแขน

แต่ละขั้นเขียน **`<ท่าแขนซ้าย>/<ท่าแขนขวา>`**:

| เขียน | ความหมาย |
|---|---|
| `act1/act2` | แขนซ้ายไป `act1` แขนขวาไป `act2` — **เริ่มพร้อมกันและถึงพร้อมกัน** |
| `act1/-` | แขนซ้ายไป `act1` แขนขวา**อยู่นิ่ง** (`-` หรือ `still`) |
| `-/act3` | แขนซ้ายอยู่นิ่ง แขนขวาไป `act3` |
| `wait=1.0` | หยุดรอ 1 วินาที (ทั้งสองแขน) |

- ขั้นถัดไปเริ่มเมื่อ**ทุกแขนถึงแล้ว**
- `-` (อยู่นิ่ง) ไม่ได้จำตำแหน่งไว้ — แขนค้างอยู่ตรงที่ขั้นก่อนหน้าพาไป ไม่ใช่วิ่งกลับไปที่ไหน
- ขั้นแรกของโปรแกรมควรเป็นท่าที่รู้ตำแหน่งแน่นอนของทั้งสองแขน (เช่น `rest/rest`)
- โปรแกรมแบบเก่า (มีแต่ชื่อท่า ไม่มี `/` เช่น `demo`) = แขนซ้ายอย่างเดียว ยังเล่นได้

ตัวอย่าง `arm show pick2`:

```text
โปรแกรม 'pick2' (5 ขั้น)
  ขั้น  แขนซ้าย (1)  แขนขวา (2)
     1  rest         rest
     2  act1         act1
     3  act2         still
     4  wait 1 s
     5  rest         rest
```

**ไม่มีการเช็กการชนตอน `arm run` / `arm goto`** (รวมสองแขนชนกันเอง) — แขนเดินตรงจากท่าหนึ่งไปอีกท่า
ไม่ได้เดินตามเส้นทางที่ MoveIt วางไว้ตอนจัดท่า ทดสอบโปรแกรมใหม่ด้วยความเร็วต่ำก่อน ถ้าเฉียดให้เพิ่มท่าคั่นกลาง

### แก้ท่า / แก้โปรแกรม

| อยากทำ | ทำยังไง |
|---|---|
| **แก้ท่าเดิม** | `arm goto <แขน> <ท่า>` → ปรับใน MoveIt (แท็บ Joints → Plan & Execute) → `arm teach <แขน> <ชื่อเดิม>` (ทับของเดิม แสดงค่าเก่า/ใหม่ให้ดู) |
| **แก้ลำดับในโปรแกรม** | สั่ง `arm program <ชื่อเดิม> <ขั้นใหม่ทั้งหมด...>` ทับได้เลย |
| **ลบท่าที่โปรแกรมยังใช้อยู่** | ระบบจะไม่ยอมและบอกว่าโปรแกรมไหนใช้ — แก้/ลบโปรแกรมนั้นก่อน แล้วค่อย `arm delete` |
| **เปลี่ยนชื่อท่า** | `arm goto <แขน> <ชื่อเก่า>` → `arm teach <แขน> <ชื่อใหม่>` → แก้โปรแกรมให้ใช้ชื่อใหม่ → `arm delete <แขน> <ชื่อเก่า>` |

แก้ไฟล์ท่าแล้วไม่ต้องรีสตาร์ทอะไร — ตัวเล่นโปรแกรมอ่านไฟล์ใหม่ทุกครั้งที่สั่ง

### จัดท่าด้วย MoveIt (RViz บนจอ Pi)

**เปิด MoveIt**

1. เปิดระบบแขนไว้ก่อน (`arm start` ในหน้าต่าง 1) — MoveIt สั่งแขนผ่านระบบนี้
2. เปิด **Raspberry Pi Connect → Screen sharing** ให้เห็นเดสก์ท็อป Pi
3. บนเดสก์ท็อป Pi กดไอคอน **Terminal** (รูปจอดำ `>_` แถบบนซ้าย) เปิดหน้าต่างใหม่
4. พิมพ์ `arm moveit` แล้ว Enter — รอ 20–30 วินาที หน้าต่าง **RViz** ขึ้นพร้อมโมเดลสองแขน เสา หัว และกล้อง
5. ปล่อยหน้าต่าง Terminal นี้เปิดไว้ (ปิด MoveIt = กด `Ctrl+C` ในหน้าต่างนี้)

ถ้าขึ้น `✗ เปิดระบบแขนก่อน` = ยังไม่ได้ `arm start` · ถ้า RViz ไม่ขึ้น = เดสก์ท็อป Pi ยังไม่ได้ล็อกอิน
(ต้องเห็นหน้าจอใน Pi Connect ก่อน)

**จัดท่าและบันทึก**

1. แผง MotionPlanning → ช่อง **Planning Group** เลือก `left_arm`, `right_arm` หรือ `both_arms`
2. แท็บ **Joints** เลื่อนมุมทีละแกน (หรือลากลูกบอลที่ปลายแขน) — แขนสีส้มโปร่งขยับให้ดูก่อน แขนจริงยังไม่ขยับ
3. แท็บ **Planning** → Velocity Scaling ตั้งไว้ **0.3** แล้ว (อย่าเกิน 0.3) → กด **Plan & Execute** → **แขนจริงขยับ**
   - ตอน Plan, MoveIt เช็กการชนให้: แขนกับแขน และแขนกับเสา/หัว/กล้อง — ถ้าชนจะ Plan ไม่ผ่าน
4. แขนถึงท่าแล้ว เปิดอีกหน้าต่าง: `arm teach <แขน> <ชื่อท่า>`
5. ทำซ้ำทุกท่า แล้ว `arm program ...` → ทดสอบ `arm run <ชื่อโปรแกรม>` (ต้องเปิด `arm player` ไว้)

ปุ่ม **Stop** ในแผง Planning หยุดแขนกลางทางได้ · ฉุกเฉินปิดสวิตช์ไฟแขน

**ลำดับเต็มตอนจัดท่า**

```text
หน้าต่าง 1:                    arm start       → เปิดค้าง
หน้าต่าง 2:                    arm player      → เปิดค้าง
หน้าต่าง 3 (เดสก์ท็อป Pi):     arm moveit      → เปิดค้าง (RViz ขึ้นบนจอ Pi)
หน้าต่าง 4:                    arm teach ...   / arm program ... / arm run ...
```

### สั่งจากรีโมท FlySky

| สวิตช์ | ทำอะไร |
|---|---|
| **CH6** (ตอนนี้คือ **SWC** 3 ระดับ) บนสุด → ล่างสุด | เล่นโปรแกรม `1` (ครั้งเดียวต่อการโยกหนึ่งครั้ง) — ตำแหน่งกลางไม่นับ |
| **CH8** (**SWD**) ขึ้น → ลง | หยุดแขนทันที (ทุกแขน) — และระหว่างที่ SWD ลงค้างอยู่ สั่งเล่นไม่ได้ |

**ต้องมี:** Mega เสียบ USB เข้า Pi · รีโมทเปิดอยู่ · `arm start` และ `arm player` เปิดอยู่ แล้วเปิดอีกหน้าต่าง:

```text
หน้าต่าง 4:  arm remote        → เปิดค้างไว้ (เปลี่ยนโปรแกรมได้: arm remote pick2)
```

หน้าต่างนี้แสดงทุกครั้งที่โยกสวิตช์ (`สวิตช์ SWB=U SWD=U`) และผลจากแขน (`แขนรายงาน: 1:ok`)
ถ้ายังไม่ได้เปิด `arm player` ก็เปิดทดสอบสวิตช์ได้ — เห็นผลบนจอแต่แขนไม่ขยับ

**กันสั่งมั่ว:**

- สั่งเฉพาะจังหวะโยก ขึ้น → ลง · สวิตช์ลงค้างไม่สั่งซ้ำ จะเล่นอีกรอบต้องยกขึ้นแล้วโยกลงใหม่
- เปิดระบบตอนสวิตช์ลงอยู่ = ไม่สั่ง (ต้องเห็นสวิตช์ขึ้นก่อน)
- รีโมทดับ/หลุดสัญญาณ = ไม่สั่ง และหลังสัญญาณกลับมาต้องยกสวิตช์ขึ้นก่อน
- แขนกำลังเล่นโปรแกรมอยู่แล้วโยกอีก = ถูกปฏิเสธ (`rejected:busy`) ไม่ซ้อน

`arm remote` เปิด `relay_bridge` (คุยกับ Mega) ให้ด้วย ถ้ายังไม่ได้เปิด — ปิดด้วย `Ctrl+C` ปิดทั้งคู่
รีโมทยังขับฐานได้ตามปกติ (SWA = ARM ล้อ ไม่เกี่ยวกับแขน)

## 3. ปิด

1. ให้แขนกลับท่าพักก่อน: `arm goto left rest` และ `arm goto right rest` (หรือสร้างโปรแกรม `arm program park rest/rest` แล้ว `arm run park`)
2. `arm off` (ปิดทุกอย่างของแขน — หรือกด `Ctrl+C` ทีละหน้าต่าง)
3. ปิดไฟแขน

## 4. Calibrate

### ต้อง calibrate เมื่อไหร่

- ปิดไฟแขน (รวมทุกครั้งที่ต้องถอด/เสียบ USB — เพราะต้องปิดไฟแขนก่อน)
- แฟลชเฟิร์มแวร์ Teensy ใหม่ หรือเปลี่ยนทิศมอเตอร์ด้วย `arm dir`
- แขนชนอะไร หรือสายพานรูด (ตำแหน่งที่ระบบจำไว้จะไม่ตรงกับแขนจริงแล้ว)

ถ้าไม่ได้เกิดเรื่องพวกนี้ ข้ามขั้น calibrate ไปที่ `arm start` ได้เลย · calibrate ได้เฉพาะตอนระบบแขนปิดอยู่

### สั่งยังไง (ทีละแขน)

```text
arm calibrate left              ใช้ลำดับที่ตั้งไว้ใน LEFT_CAL_ORDER (ยังไม่ตั้ง = ต้องใส่ลำดับเอง)
arm calibrate left 5            ข้อเดียว — ไว้ไล่ดูว่าข้อไหนพามือไปชน
arm calibrate left 6 5 4 1 2 3  ทีละข้อตามลำดับ (แต่ละข้อหาสวิตช์ → ถอย → กลับท่าพัก ก่อนไปข้อถัดไป)
arm calibrate left 456 123      กลุ่มละหลายข้อพร้อมกัน
arm calibrate left all          6 ข้อพร้อมกันแบบต้นฉบับ (มือที่ติดปลายแขนอาจชน)
```

ระหว่างทำจะแสดงผลทีละข้อ:

- `✓ J5 เจอสวิตช์แล้ว` — ข้อนั้นผ่าน
- `✗ J5 ... FAIL` — หมุนครบระยะแล้วไม่เจอสวิตช์ บอร์ดหยุดข้อนั้นให้เอง (ไม่หมุนต่อจนชน) และโปรแกรมจบพร้อมแจ้ง
  มักเป็นมอเตอร์ข้อนั้นหมุนกลับด้าน → `arm dir <แขน> <6 หลัก>` แล้ว calibrate ข้อนั้นใหม่ · หรือสวิตช์/สายหลุด
- `USB หลุดระหว่าง calibrate` — ปกติตอนมอเตอร์หมุน แขนทำต่อเอง โปรแกรมรอต่อใหม่ให้
- จบเมื่อขึ้น `calibrate ครบตามที่สั่งแล้ว` — **ไม่ต้องกด Ctrl+C**

**ระหว่าง calibrate:**

- ครั้งแรกหลังย้ายสาย ดูให้แน่ใจว่าแขนที่ขยับคือแขนที่สั่ง — ไม่ใช่ หรือมือกำลังจะชน ให้ปิดไฟแขนทันที
- รอบแขนโล่ง สาย USB หย่อนพ้นรัศมีแขน (ฐาน J1 หมุนไปถึง −170°) อีกแขนต้องไม่อยู่ในทาง
- ข้อที่ไม่ได้สั่งไม่ขยับ — แต่ถ้าเพิ่งเปิดไฟแขน ต้อง calibrate ให้ครบทั้ง 6 ข้อก่อนใช้งาน

### ทิศมอเตอร์ (`arm dir`)

`arm dir <left|right> <J1..J6>` — 6 หลัก 0/1 ตามลำดับ J1..J6, `1` = ข้อนั้นมอเตอร์หมุนกลับด้านจากปกติ
เช่น `arm dir right 000010` = J5 แขนขวากลับทิศ · `arm dir right 000000` = ปกติทุกข้อ
เก็บในบอร์ดของแขนนั้น ใช้ทั้งตอน calibrate และตอนวิ่ง — ตั้งแล้วต้อง calibrate ข้อนั้นใหม่

## 5. ปัญหาที่เคยเจอ

| อาการ | สาเหตุ | แก้ |
|---|---|---|
| `Waiting for at least 1 matching subscription(s)` | ตัวเล่นโปรแกรมไม่ได้เปิด | `arm player` ในอีกหน้าต่าง |
| `ระบบแขนเปิดอยู่แล้ว — ห้ามเปิดซ้อน` | มีระบบแขนเปิดอยู่แล้ว | ใช้ตัวเดิม หรือ `arm off` แล้วเริ่มใหม่ |
| `Controller already loaded`, `Unknown header C1/P0/JA` | เปิดระบบแขนซ้อน 2 ชุด | `arm off` → calibrate ใหม่ |
| `หาบอร์ด Teensy แขน... ไม่เจอ` | บอร์ดยังไม่ได้ตั้งชื่อ / ไฟแขนปิด / ค้างอยู่ใน calibrate | `arm ports` ดูก่อน · ยังไม่มีชื่อ → `arm identify` · ค้าง → ปิด-เปิดไฟแขน |
| `arm ports` ขึ้น `ไม่ตอบ` | บอร์ดกำลัง calibrate หรือระบบแขนเปิดใช้พอร์ตอยู่ | รอ calibrate จบ / `arm off` |
| `มีบอร์ดชื่อ 'left' สองตัว` | ตั้งชื่อซ้ำ | `arm identify` ใหม่ |
| calibrate ขึ้น `✗ J... FAIL` | มอเตอร์ข้อนั้นหมุนกลับด้าน หรือสวิตช์/สายหลุด | `arm dir <แขน> <6 หลัก>` → calibrate ข้อนั้นใหม่ |
| calibrate แล้วมือชน | หลายข้อหมุนพร้อมกัน | calibrate ทีละข้อ หาลำดับที่ไม่ชน แล้วตั้ง `LEFT_CAL_ORDER` / `RIGHT_CAL_ORDER` |
| ขยับใน RViz แล้วแขนจริงหมุนกลับทิศกับโมเดล | ทิศข้อนั้นในบอร์ดกับในโมเดลไม่ตรงกัน | ตรวจข้อนั้นด้วย calibrate ก่อน แล้วแจ้งให้แก้ (อย่าแก้ไฟล์โมเดลเอง) |
| `path tolerance violation` | สั่งเร็วเกิน มอเตอร์ตามไม่ทัน | ใช้ความเร็วปกติ (0.19) ห้ามเกิน 0.22 |
| สายพานรูด / ท่าเพี้ยน | แขนยื่นไกลแล้วเร่ง-หยุดแรง หรือสายพานหย่อน | ให้ช่างตั้งความตึง → calibrate ใหม่ |
| `แขนขวาไม่มีท่า '...'` | ท่านั้นยังไม่ได้ teach ให้แขนนั้น (ท่าแยกตามแขน) | `arm list` ดูชื่อท่าของแต่ละแขน → `arm teach <แขน> <ท่า>` |
| โยกสวิตช์รีโมทแล้วแขนไม่ขยับ | ยังไม่ได้ยกสวิตช์ขึ้นก่อน / SWD ลงอยู่ / ตัวเล่นโปรแกรมไม่เปิด | ดูหน้าต่าง `arm remote` ว่าขึ้นอะไร — ยกสวิตช์ขึ้นแล้วโยกลงใหม่ |
| `arm remote` ขึ้น `ไม่เจอ Mega` | Mega ไม่ได้เสียบที่ Pi | ปิดไฟแขน → เสียบ USB ของ Mega เข้า Pi |
| RViz ไม่ขึ้น | เดสก์ท็อป Pi ยังไม่ได้ล็อกอิน | เปิด Pi Connect ให้เห็นหน้าจอก่อน แล้ว `arm moveit` ใหม่ |

## 7. คำสั่งเต็ม (ถ้าคำสั่ง `arm` ใช้ไม่ได้)

เข้า container ก่อนทุกหน้าต่าง: `docker exec -it humanoi_ros bash`

```bash
# หาพอร์ต / ตั้งชื่อบอร์ด (ระบบแขนต้องปิดอยู่)
ros2 run ar_dual ar_ports.py --list
ros2 run ar_dual ar_ports.py                 # พิมพ์ left=<พอร์ต> right=<พอร์ต>
ros2 run ar_dual ar_ports.py --identify
ros2 run ar_dual ar_ports.py --dir <พอร์ต> 000010
# calibrate (ทีละแขน)
ros2 run ar_dual ar_calibrate.py <พอร์ตแขน> 6 5 4 1 2 3
# เปิดระบบสองแขน (left_hw/right_hw = real | mock)
ros2 launch ar_dual dual_hardware.launch.py left_port:=<พอร์ตซ้าย> right_port:=<พอร์ตขวา> left_hw:=real right_hw:=real
# ตัวเล่นโปรแกรม
ros2 launch ar_program arm_program.launch.py speed:=0.19
# สั่งงาน
ros2 topic pub --once /arm/run std_msgs/msg/String "{data: pick2}"
ros2 topic pub --once /arm/run std_msgs/msg/String "{data: '@right:rest'}"   # = arm goto right rest
ros2 topic pub --once /arm/stop std_msgs/msg/Empty "{}"
ros2 run ar_program teach --list
ros2 run ar_program teach --show pick2
ros2 run ar_program teach <ชื่อท่า> --arm left
ros2 run ar_program teach --program pick2 rest/rest act1/- wait=1.0 -/act2
ros2 run ar_program teach --delete <ชื่อท่า> --arm right
ros2 run ar_program teach --delete-program pick2
```

MoveIt (นอก container บนเดสก์ท็อป Pi): `bash ~/Humanoi/scripts/arm_moveit.sh`

คำสั่ง `arm` คือ `~/Humanoi/scripts/arm.sh` (alias อยู่ใน `~/.bashrc` ของ Pi)
