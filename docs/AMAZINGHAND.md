## 1. ฮาร์ดแวร์

| ชิ้น | รายละเอียด |
|---|---|
| มือ | AmazingHand (ชุด AliExpress) **มือขวา** 4 นิ้ว |
| servo | Feetech SCS0009 × 8 (model 1284) ลิมิตโรงงาน raw 20–1003 ≈ ±144° |
| ID | นิ้วชี้ 1-2 · กลาง 3-4 · นาง 5-6 · โป้ง 7-8 (ตัวแรกของคู่ = a, ตัวที่สอง = b) |
| บอร์ดต่อ | Waveshare Bus Servo Adapter (A) — CH343 USB `1a86:55d3` serial `5B91044327` · jumper ที่ **B** (USB) |
| พอร์ตบน Pi | `/dev/serial/by-id/usb-1a86_USB_Single_Serial_5B91044327-if00` (เกมหาเองจาก USB ID) |
| baud | ตอนนี้ **250000** (ค่าร้าน) — เคยตั้งเป็น 1 Mbps เมื่อ 29 ก.ย. แต่ 20 ต.ค. เจอกลับเป็น 250000 เอง |
| ไฟ | แหล่งจ่าย **6 V ≥3 A** เข้าช่องไฟของบอร์ด → ที่ servo ได้ 5.1–5.4 V (บอร์ดทำไฟตก ~0.8–1 V) |

**กฎไฟ:** servo **ห้ามเกิน 7.4 V** · บอร์ดเขียนรับ 9–12.6 V แต่ส่งไฟตรงเข้า servo **ห้ามใช้** · ไฟ 5 V ไม่พอ
(servo ได้แค่ 3.9–4.3 V ต่ำกว่า 4.5 V ที่มันยอมทำงาน) · วัดมิเตอร์ที่ช่อง V–G ของบอร์ดก่อนเสียบมือทุกครั้งที่เปลี่ยนแหล่งจ่าย

**ต่อ:** ไฟ 6 V → บอร์ด · jumper B · USB บอร์ด → Pi · เปิดพอร์ตได้ทีละโปรแกรม (เกม / เครื่องมือคาลิเบรต / tools บน Windows)

## 2. ซอฟต์แวร์ทำงานยังไง

แพ็กเกจ `ros2_ws/src/humanoi_games` (รันใน container `humanoi_ros` บน Pi)

### amazinghand_node — ตัวคุมมือ (ตัวเดียวที่เปิดพอร์ตมือ)

ตอนเชื่อมต่อทำตามลำดับ ไม่ผ่านขั้นไหน = **ไม่เปิดแรงบิด ไม่ขยับ** แล้วบอกเหตุผลใน log:

1. หาพอร์ตจาก USB ID ของบอร์ด
2. หา baud เอง (ลอง 1 Mbps ก่อน แล้วไล่ค่าอื่น — อ่านอย่างเดียว)
3. servo ต้องตอบครบ 8 ตัว และไฟ **4.8–7.4 V** ทุกตัว
4. อ่านขีดจำกัดมุมจาก EEPROM ของ servo แต่ละตัว (อ่านไม่ได้/ค่าแปลก = ใช้ ±144° แล้วเตือน)
5. สั่งให้ถือท่าปัจจุบันก่อน แล้วค่อยเปิดแรงบิด (นิ้วไม่กระตุก)

หัวข้อ ROS:
- `/hand/gesture` (รับ) ชื่อท่า หรือ `relax` = ปลดแรงบิด · คำสั่งใหม่ตัดท่าเคลื่อนไหวที่ค้างอยู่ทันที
- `/hand/status` (ส่ง) `ready` · `gesture:<ท่า>` · `relaxed` · `error:<เหตุผล>`

เป้าหมายที่เกินขีดจำกัดของ servo ถูกจำกัดไว้ที่ขอบ (เตือนใน log) · ปิดโหนด = ปลดแรงบิดทุกตัว (นิ้วอ่อนลงเป็นกำ)

### มุมนิ้วคิดยังไง

แต่ละนิ้วมี servo 2 ตัว: **หมุนสวนกัน = งอ/เหยียด**, **หมุนไปทางเดียวกัน = เอียง/กาง**

```
servo a = งอ + เอียง + กางเพิ่ม        servo b = -งอ + เอียง + กางเพิ่ม      (องศา)
```

ค่าคาลิเบรตต่อนิ้ว: **แบสุด** (งอตอนแบ), **กำสุด** (งอตอนกำ), **เอียง** (ให้นิ้วตั้งตรง)

### ท่ามือ (`hand_poses.py`)

| ท่า | นิ้วชี้ | นิ้วกลาง | นิ้วนาง | นิ้วโป้ง | ใช้ตอน |
|---|---|---|---|---|---|
| `rock` ค้อน | กำสุด | กำสุด | กำสุด | กำสุด | หุ่นออกค้อน |
| `paper` กระดาษ | แบสุด | แบสุด | แบสุด | แบสุด | หุ่นออกกระดาษ / จบเกม |
| `scissors` กรรไกร | แบ + กาง 25° | แบ − กาง 25° | กำสุด | กำสุด | หุ่นออกกรรไกร |
| `windup` ง้าง | กึ่งกลาง | กึ่งกลาง | กึ่งกลาง | กึ่งกลาง | ตอนเป่า-ยิ้ง |
| `like` ชูโป้ง | กำสุด | กำสุด | กำสุด | แบสุด | หุ่นแพ้ |
| `point` ชี้ | แบสุด | กำสุด | กำสุด | กำสุด | ส่ายนิ้ว |
| `victory` (เคลื่อนไหว) | กรรไกร ↔ หุบ 3 รอบ | | | | หุ่นชนะ |
| `nonono` (เคลื่อนไหว) | ชี้แล้วส่าย ±35° 3 รอบ | | | | ไม่เห็นมือผู้เล่น |

### hand_calibrate — คาลิเบรตทีละนิ้ว

```bash
arm hand-calibrate            # ปิดเกมก่อน (ใช้พอร์ตเดียวกัน)
arm hand-calibrate --reset    # เริ่มใหม่จากค่าเดโม (ค่าเดิมเปลี่ยนชื่อเป็น .bak-<เวลา>)
```

ตอนเปิดพิมพ์ baud และขีดจำกัดที่อ่านจาก servo ทุกตัว แล้วทีละนิ้ว (นิ้วอื่นกำไว้):

1. **ท่าแบสุด** (เริ่มที่นี่): `+` / `-` แบมาก/น้อย · `l` / `r` เอียงจนนิ้วตั้งตรง
2. กด `c` → **ท่ากำสุด**: `+` / `-` จนปลายนิ้วแตะฝ่ามือพอดี (servo ครางค้าง = เกิน กด `-`)
3. กด `n` → นิ้วถัดไป (บันทึกให้) · `q` บันทึกแล้วออก · `x` ออกไม่บันทึก · ใส่ตัวเลขได้ เช่น `+5`

บรรทัดคำสั่งบอกค่าปัจจุบันและมุม servo จริง เช่น `[นิ้วชี้ · ท่ากำสุด] แบ -94 · กำ +112 · เอียง -20 · servo ID1 +92 ID2 -132`
ถ้าไม่ยอมแก้จะบอกตัวเลข เช่น `servo ID2 ต้องไป -150° แต่หมุนได้ -144..+144°`

ค่าเก็บที่ `/humanoi_ws/src/humanoi_games/config/middle_pos.json` (บน Pi = `~/Humanoi/ros2_ws/src/...`)
— เกมโหลดตอนเปิด (คาลิเบรตแล้วต้องเปิดเกมใหม่) · ไฟล์รูปแบบเก่า (middle_pos) แปลงให้เองโดยท่าไม่เปลี่ยน · ไม่มีไฟล์ = ท่าเหมือนเดโมของ Pollen

### สั่งมือตรงๆ (ทดสอบ)

```bash
docker exec -it humanoi_ros /entrypoint.sh ros2 run humanoi_games amazinghand_node
docker exec humanoi_ros /entrypoint.sh ros2 topic pub --once /hand/gesture std_msgs/msg/String "{data: paper}"
```

เครื่องมือบน Windows (`Desktop\AmazingHand\tools\`, ใช้ตอนเสียบมือเข้า PC): `scan_servos.py` (อ่านอย่างเดียว เช็กไฟ),
`relax.py`, `find_limits.py`, `finger_test.py` — ตั้งค่าเริ่มไว้ 1 Mbps **ต้องใส่ `--baud 250000`** ตอนนี้

## 3. ปัญหาที่ยังค้าง

| # | ปัญหา | ผล | ทางแก้ / สถานะ |
|---|---|---|---|
| 1 | **นิ้วมีระยะฟรี** (เจอ 20 ต.ค.) | ตำแหน่งนิ้วไม่ซ้ำเดิม คาลิเบรตแล้วก็ไม่นิ่ง | ขันสกรูแตร servo และข้อต่อก้านนิ้วให้แน่น (ปิดไฟมือก่อน) **ก่อน**คาลิเบรต — ซอฟต์แวร์แก้ไม่ได้ |
| 2 | **แตร servo น่าจะใส่คลาดหลายฟัน** | ท่าตรงของมือนี้ต่างจากมือตัวอย่างมาก (นิ้วกลางต้องงอกลับ ~57°, นิ้วชี้ต้องเอียงเกิน 30°) ช่วงหมุนที่เหลือของ servo น้อย — กำ/แบอาจชนขอบก่อนนิ้วถึง เช่นนิ้วชี้เอียง −20 → servo ID2 ชนขอบที่กำราว +123 | แก้ถาวร: ถอดแตรใส่ใหม่ให้ตรงฟัน (ฟันละ 18°) ค่าคาลิเบรตจะกลับมาใกล้ 0 · ตอนนี้ชดเชยด้วยซอฟต์แวร์ |
| 3 | **คาลิเบรตยังไม่เสร็จ** | ไฟล์ล่าสุด (20 ต.ค. 16:26) = ท่าตรงทุกนิ้ว + กำสุดนิ้วชี้เท่านั้น · ค่าจากรอบหลัง (นิ้วชี้ แบ −94 / กำ +112 / เอียง −20) **ไม่ได้บันทึก** | แก้ข้อ 1 ก่อน แล้วคาลิเบรตใหม่ทั้ง 4 นิ้ว (`--reset` ได้) |
| 4 | **ขีดจำกัด servo ที่อ่านจาก EEPROM ยังไม่ได้ยืนยัน** | rustypot 1.10 เคยอ่านค่าดิบสลับไบต์ (5120/−5373 แทน 20/1003) รุ่น 1.13.1 ที่ใช้ยังไม่ได้เช็กกับของจริง | ตอนเปิด `arm hand-calibrate` ดูบรรทัด "ขีดจำกัดที่อ่านจาก servo" ควรราว −144..+144 ทุกตัว · ค่าแปลกจะเตือนแล้วใช้ ±144 |
| 5 | **baud เปลี่ยนกลับเอง** (1 Mbps → 250000) | เครื่องมือบน Windows ที่ตั้ง 1 Mbps ต่อไม่ติด | โหนด/เครื่องมือบน Pi หาเอง · Windows ใส่ `--baud 250000` · สาเหตุยังไม่ทราบ |
| 6 | **ท่ากรรไกร/ชี้/ส่ายนิ้ว ใช้มุมกางตายตัวของเดโม** (±25°, ±15°, ±35°) | อาจดูไม่สวยกับมือนี้ | ปรับใน `hand_poses.py` หลังคาลิเบรตเสร็จ |
| 7 | **ไฟล์คาลิเบรตอยู่บน Pi เท่านั้น** เป็นของ root ไม่อยู่ใน git | ถ้า SD เสียค่าหาย | สำรองเอง / ดึงกลับ PC ก่อน commit (แบบ programs.yaml) — การ sync จาก PC ไม่ทับไฟล์นี้ |
| 8 | **ไลบรารีลงใน container ที่รันอยู่** (rustypot 1.13.1, mediapipe) | สร้าง container ใหม่ = หาย | `docker/Dockerfile` มีชั้นนี้แล้ว — build image ใหม่ตอนว่าง (คำสั่งลงเองอยู่ใน RPS_GAME.md) |
| 9 | **USB บน Pi เต็ม** (4 ช่อง) | ใช้แขนสองข้าง + มือ + กล้องพร้อมกันไม่ได้ | USB hub มีไฟเลี้ยง · ตอนเล่นเกมใช้แขนซ้าย + Nano + กล้อง + มือ พอดี 4 ช่อง |
| 10 | ตำแหน่ง/มุมยึดมือใน URDF ยังเป็นค่าเดา | มีผลแค่ภาพใน RViz / เช็กชนใน MoveIt | วัดจริงแล้วแก้ใน `ar_dual/urdf` |
